# Project lessons

Recurring gotchas that bind from the first task of every session. Keep entries short, factual, and actionable.

## "No-content-escapes" guards: confine the semantic surface, don't enumerate spellings (2026-08-10)
Two invariants in Phase 3A took 4–5 review rounds each because every fix closed the named instance and left the class. The log tripwire (Phase 1, rounds 3–6) hand-listed which record fields to scan; each round a peer found one more field. The config trust-boundary guard (Phase 3, rounds 10–13) hand-listed which `NoteRequest` constructor spellings to reject; each round a peer found another (`model_validate_strings`, `TypeAdapter`, `__pydantic_validator__`…). Both only converged when the fix stopped enumerating and started deriving/confining the whole surface: the tripwire derived its scanned-field set from `LOG_FORMAT`; the guard rejected every runtime reference to the class except an exact allow-list of call nodes with pinned counts. **When a control claims "no X can escape", any allow-list of specific forms is a bug generator — guard the semantic surface (all references, minus a pinned allow-list) so a new form fails toward safety by default.** A docstring may claim only what the structure enforces; name any out-of-scope residue explicitly.

**Addendum (2026-09-04) — a property held by construction closes a review class; an epsilon or a named residue does not.** The Task 2.3a harness took six cross-family peer rounds (62–67: 5 → 4 → 2 → 2 → 2 → 0) on two classes, each round shrinking the residue of the previous fix. Label-order independence went alphabetical tie-break → epsilon tie at the two named sites → a moving-anchor epsilon chain (non-transitive nearness) → float-sum operand order, and closed only when every number became a function of the candidate SET (a fixed global maximum, a band around it, then count) aggregated through `math.fsum`, whose correctly-rounded result is order-independent by definition. Fail-closed teardown went sequential cleanup legs → a fail-open `Path.exists()` → `ignore_errors=True` swallowing what the accumulator was meant to record, and closed only as a `finally` chain with a failure accumulator, a direct `os.stat` probe that counts nothing but `FileNotFoundError` as gone, and a docstring stating exactly that plus the one residue no user-space code controls. The tell that a class is still open: the fix is a tolerance, an exception for the instance found, or a comment naming what the code does not do.

## Corrupt pywin32 `gen_py` cache breaks the SAPI test fixture (2026-08-10)
Symptom: `tests/test_sapi_fixture.py` fails with `AttributeError` in `win32com/client/gencache.py` (e.g. 7 failures) on an otherwise-green tree. Cause: a stale/corrupt generated typelib cache at `%LOCALAPPDATA%\Temp\gen_py`. Fix (works from an agent shell too — this one is NOT MSIX-hidden): `rm -rf "$LOCALAPPDATA/Temp/gen_py"`, then re-run pytest; the cache regenerates. Verify a pre-existing baseline failure is env, not code, by deleting the cache before blaming the diff.

## Agent shells are MSIX-virtualized on this host (2026-07-28)
All agent/composer shells on this machine run inside the Claude desktop app package (`Claude_pzs8sxrjxfjjc`). Writes to `%LOCALAPPDATA%` (and similar known folders) are silently redirected into the package's `LocalCache`, leaving links at the real path that user-launched processes cannot traverse. Consequences:
- Anything meant for the user-visible `%LOCALAPPDATA%\ClinikoScribe\` (model downloads via `scripts/setup-models.py`, host registration artifacts) must be run by the user from a normal terminal or Explorer, never from an agent shell.
- Agent-run tests cannot detect this divergence — they see the virtualized view and pass. Only a live user launch verifies user-context filesystem state.
- Symptom signature: a path exists for agent shells but raises `FileNotFoundError` for Explorer-launched apps. Fix pattern: user-context copy out of `%LOCALAPPDATA%\Packages\Claude_pzs8sxrjxfjjc\LocalCache\Local\...` (see plan round 22, Phase 2 plan).

## A spawned agent must not end its turn while its children run (2026-08-02)
Four executors in the Phase 2 loop run spawned work — codex peer rounds, review-lens subagents — and then ended their turn waiting for it. A headless role terminates at turn end, so the children are orphaned and their results are never consumed; the composer had to salvage each one (stage-2 peer round 3, stage-3 round 8, stage-10 and stage-12 lens fleets). Foreground every child and wait synchronously in the same turn; if one wait cannot span the work, re-enter bounded waits in that same turn rather than ending it.

## Give executors facts, not a big document to read (2026-08-02)

## Give codex peers a basetemp outside the repo (2026-08-04)
Two of four peer rounds in the Phase 3A stage-1 run ran pytest and left temp directories INSIDE the repo (`.pytest-peer-review-round3/`, `desktop/.pytest-tmp-peer-round4/`, `desktop/tmpjsi6ocul/`) with ACLs that no agent shell can read or delete — `Get-ChildItem`, `takeown /R /D Y` and `icacls /grant` were all denied, so they became a manual cleanup task for the user. Round 3's happened to self-clean on exit; round 4's did not, so do not rely on it. Put in every peer prompt: do not create files or directories inside the repository, and if you run pytest at all pass `--basetemp` outside it. Better still, tell the peer not to run the suite — the executor's results are already recorded and review, not re-validation, is the peer's job. Stating this in round 6's prompt prevented a third occurrence.

## The escape check is blind to unreadable directories (2026-08-04)
`OWNERSHIP: escape-check` digests the **stdout** of `git status --short`, but git reports a directory it cannot open on **stderr** (`warning: could not open directory '…': Permission denied`). A peer-created directory with a restrictive DACL therefore leaves the digest unchanged and the record reads `result=clean` while a new, unreadable directory sits in the working tree. It was caught only by reading stderr. When a spawned role may create in-repo paths, check `git status` stderr as well as the escape-check verdict — the mechanical check alone is not sufficient evidence that nothing was created.

## Put the round-bookkeeping contract in the peer and fix prompts (2026-08-04)
`loop-history-check.py` stopped the stage-1 loop twice on bookkeeping, not code: once because a round block was PREPENDED (rounds must append in strictly increasing file order), once because a closed round had no `Review History` line (the seat that finishes a round owns its summary line — and when a line already exists from an earlier seat, it is UPDATED IN PLACE, never appended alongside). Each cost a full executor activation to repair. Stating all three rules in the round-6 peer prompt and the fix-leg prompt prevented further failures. Note the checker earned its keep: an executor misplaced a history line in the same run and its own re-run caught it before exit.

## A concurrency "class-closed" claim needs an exhaustive consumer enumeration — and even then, re-verify (2026-08-12)
Phase 6's `SessionController` custody hardening took SIX cross-family peer rounds (27–32), and each new "the class is now closed" claim was falsified by the next round: a global reservation (round 27) missed `complete()` (found round 29); an entry-by-entry enumeration (round 29) missed the `Discard`+admitted-`Start`+recovery composition (round 30); the target-aware fix (round 30) assembled its protected-id set through two non-atomic reads (round 31); and even after that, `transcribe()` was still an unguarded reservation consumer (round 32). The recurring error: reasoning about custody entry points **separately** when the deliberately-admitted concurrent `start()` changes a session's reachability while another operation's reservation is live. Two lessons. **(1)** When a concurrency fix claims to close a class, enumerate every custody-mutating/using consumer and prove each honours the one serialization signal — the enumeration is necessary but has been wrong until it is both exhaustive and cross-checked by an independent (cross-family) reviewer. **(2)** Know when to stop point-fixing: all six findings required a non-GUI-thread custody caller that does not exist in the shipped single-GUI-thread, queued-signal app, so the honest resolution was to fix the known consumers and **document full arbitrary-thread safety as a bounded residue** rather than chase edges indefinitely — fix the claim (the docstring) to match what the structure enforces, and name the residue. This is the "claim outruns the enforcing structure" family (log tripwire, config guard) at the concurrency layer.

## Docs-accuracy phases hit "claim outruns the enforcing structure" too — and only the cross-family peer catches it (2026-08-14)
Phase 8 (documentation) reconciled the security docs to Phases 1–3A. The in-session same-family `/review-loop` (rounds 38–39) passed the new prose clean, but the cross-family codex peer found **13 accuracy findings across 4 rounds (5 → 4 → 1 → 3 → 0)** — every one a security-doc claim that asserted a stronger guarantee than the code enforces: an unconditional 24 h retention cap (where `app.sweep_protected_ids` exempts live/queued/recovery stores), config "no patient data/secrets" as *enforced* (where `note_config` validates structure only), "≤15 min"/"destroyed at 24 h" as hard bounds (where the sweep is a best-effort `QTimer` cadence and `sweep_sessions` retains on I/O error), "signed-note content" for an encrypted *local draft*, "binds every canonical section" (ignoring `intentionally_unmapped`). Two lessons. **(1)** The "claim outruns structure" family (log tripwire, config guard, custody residue) applies to DOCS prose exactly as to code — a threat-model/retention/data-flow claim is a control claim, and it must state only what the structure enforces, naming residue. **(2)** A docs-reconciliation phase NEEDS the cross-family peer pass (the same-family author shares the blind spot), and each finding must be fixed as a **CLASS** — grep the whole doc surface for every sibling of the phrasing, not just the cited line — or the next round finds the sibling the instance-patch left (rounds 40→41 were exactly that miss). Budget for a multi-round peer pass on any security-doc phase.

## A `perms=scoped` executor with no Bash grant cannot emit `VERIFY_OK` (reconcile from the handoff) (2026-08-14)
The spawn-wrapper footer tells the spawned role to run `python3 scripts/loop-journal.py emit VERIFY_OK ... children=<n>` as its atomic final step. Under `perms=scoped` with an empty `LOOP_ALLOWED_TOOLS` (the right default for a docs phase — the executor only edits Markdown), the executor has NO Bash grant, so that emit is permission-blocked (and the `$LOOP_PROBE_LOG` form is additionally hard-blocked by the `simple_expansion` hook). There is then no `VERIFY_OK` line in the probe log — this is EXPECTED, not a hang: a docs executor spawns no children, so the composer reconciles `children=0` from the clean `ROLE: handoff` (which the role writes as plain final-message text, needing no grant). If you actually need the executor to self-emit journal records or run any helper, grant `Bash(python3 scripts/loop-journal.py:*)` in `LOOP_ALLOWED_TOOLS`; otherwise reconcile the census from the handoff sentinel. (Pairs with the EXIT:4 census-gap note below — both are "the wrapper's self-census evidence is absent on this host; classify from the role's own clean handoff".)

## `/execute-loop` spawn on this Windows / Git-Bash host: POSIX paths + a benign EXIT:4 (2026-08-13)
Two run-mechanics gotchas that will otherwise cost a fresh `/execute-loop` run time on this machine. (1) **Path form.** `scripts/loop-spawn-wrapper.sh` `require_abs()` accepts only paths beginning with `/`, so every `LOOP_*` path — `LOOP_CWD`, `LOOP_PROBE_LOG`, `LOOP_ROLE_LOG`, the `LOOP_ESCAPE_ROOTS` `base=`, `LOOP_PROMPT_FILE`, `LOOP_IDENTITY_FILE` — must be **POSIX `/c/…`**, never Windows `C:/…` (a `C:/…` value fails pre-START with `SPAWN_REFUSED check=params … must be an ABSOLUTE path`, exit 2, no probe-log write). MSYS auto-converts `/c/…` back to `C:/…` when the wrapper hands the path to the python helper, which is why the `OWNERSHIP: escape-check` records read `base=C:/Recording clinic software`. The `loop-journal.py` helper invoked DIRECTLY from a composer shell (sticky-ack, escape-check, emit) takes the Windows `C:/…` form instead (Windows python understands it natively). (2) **Benign EXIT:4.** Every wrapper spawn exits `EXIT:4` here — the `ps`-based survivor census cannot run under Git Bash (`OWNERSHIP: exit-census … refused=capture-failure detail="census command failed; survivor count unconfirmed"`), which the wrapper folds into exit 4. It is NOT a failure: classify it via the role's `VERIFY_OK children=0` + a clean `ROLE: handoff` + a billed terminal result. (3) **Binary.** Use the bare npm shim `~/AppData/Roaming/npm/claude` (no `.cmd`) as `LOOP_CLAUDE_BIN` — it runs cleanly from Git Bash and accepts `--model claude-opus-4-8`; the probe pins `claude.cmd` for its isolation check, but the bare shim is the one to spawn through. (4) **verify=composer** is the standing outcome here — the host's headless hooks deny the executor's compound `cd desktop && <exe>` verification and `$VAR` expansion, so the composer runs ruff/mypy/pytest and resumes the executor (`reason=composer-run`).

## When a heuristic parser keeps failing review, change the severity contract, not the parser (2026-09-03)
When successive independent review rounds each find a NEW construction that the same heuristic parser mishandles, the fix is the severity contract, not another parser rule: demote the class from a blocking error to an acknowledgeable review warning, keeping the signal. Evidence: dose rounds 21-24 ended with `dose_mismatch` review; laterality rounds 48-58 (five cross-family rounds, each finding a defect in the prior round's fix on the same surface) ended with `laterality_mismatch` review, practitioner-ratified 2026-09-03. A phrase- or connector-level exception after the second such round is the pattern that does not converge - rounds 54, 55, 56 and 57 each added one and each was overturned by the next fresh peer. The tell is a peer stopping rule of the form 'one structural attempt, then re-grade'; honour it. The decision is a practitioner safety call (a blocking check is being weakened), so it is ratified explicitly and recorded in the threat model as a responsibility boundary, never inferred.

## Preflight the CLI itself, not the probe's word for it (2026-09-04)
The `/execute-loop` wizard's probe script reported the `claude` CLI's default account logged in and listed its models, yet the first wrapper spawn of the stage-2 run died twice before any work ran: first with `authentication_failed` (the CLI's OAuth session had expired and could not refresh — `claude auth status` then showed `loggedIn: false`, while the desktop-app session was unaffected; the fix is the user's `claude auth login` in a normal terminal), then with `API Error: 400 ... version 2.1.251 or newer is required` because CLI 2.1.220 did not know `claude-fable-5-1` (both installed binaries were 2.1.220; the fix, user-confirmed, was `npm install -g @anthropic-ai/claude-code@latest`). `auth status` and a model list are not proof that a spawn will run: only the preflight harness probe — an actual throwaway `claude -p` spawn on the exact binary, model and tier the run will use — is. Never skip it, and expect it to fail after a long gap or on a newly released model id; both failures are user-fixable pauses with exact remediation, not run-ending.

## Transcribe a peer block LAST; never re-run a replace script over a plan that already holds one (2026-09-05)
A find/replace applied to the plan AFTER a peer round was transcribed rewrote the peer's verbatim quotation of the OLD text inside that block (round 71: the "What remains" clause and the Node "22.12+" quote), because the same old text the amendment targeted was, by design, quoted by the peer. It happened on an "idempotence" re-run of a patch script. Rules: transcribe the block after every other edit of that round; scope every replacement to outside the `## Review Findings Log` (or assert the match lies before the log); never re-run a replace script to prove idempotence once a block is in; when it does happen, restore from the peer's own output file, not from memory.

## Codex usage is an account-wide 5-hour window, weighted by model — budget rounds and resume cut-offs (2026-09-05)
Three facts from one day: `gpt-5.6-sol` ran three code rounds (570k tokens) inside one window without tripping; `gpt-6-astra` tripped at ~150k tokens at xhigh and at ~320k across a resume plus one round at high; when the window is spent EVERY model is refused (a `gpt-5.6-sol` probe failed with the same message), until the quoted local reset time (`try again at <time>` = five hours after the window's first call). Budget accordingly: a fresh astra plan-review round is ~130k at high, ~250-350k at xhigh; keep xhigh for the rounds that review built code. A run cut off after its reading phase is not lost — `codex exec -s read-only resume <session-id> -m <model> -c model_reasoning_effort=<level> "<write-the-round prompt>" </dev/null` (the sandbox flag goes BEFORE `resume`; `-m`/`-c` after) continues the session and saves the whole re-read; a run cut off before reading anything is simply re-run. Pairs with "Preflight the CLI itself" above: a new model id can also need a newer CLI (`gpt-6-astra` refused codex-cli 0.145.0; 0.153.4 works).

## A CI job's stdout `DeprecationWarning` lines are NOT annotations (2026-09-05)
