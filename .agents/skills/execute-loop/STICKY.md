## 4. Spawn guard — mechanical, before EVERY executor/architect spawn

1. Look up the PRIOR executor's recorded identity — the shell id / PID you recorded at its spawn; never a `pgrep` pattern.
2. Verify THAT identity is dead: the background shell reports completed/exited, or the recorded PID is gone. A quiet log or long silence is NOT dead — check, never assume.
3. Only on a confirmed-dead result, spawn the new executor and record its identity. Never a second `ROLE: start` for a phase while the prior shell is live. A live role that recorded an open gate is PAUSED, not hung — never kill it. Single-emitter ownership (DR-1): for wrapper-spawned roles the WRAPPER writes `ROLE: start` (from `LOOP_PHASE`/`LOOP_MODEL`/`LOOP_LEG`) — you mint a FRESH `LOOP_LEG` per activation (mint-fresh stays YOUR duty — a stateless wrapper cannot detect reuse; NEVER reuse a leg value within the run) and later write the matching `ROLE: end` reusing that leg VERBATIM (`leg=<the LOOP_LEG value>`; an end with no matching open activation is the end-without-start violation); you NEVER author a `ROLE: start` for a wrapper-spawned role — a composer start beside the wrapper's is the duplicate-start violation. Non-wrapper activations (codex peers) get their lifecycle via `emit ROLE:start` / `emit ROLE:end`. Liveness probes use the recorded PID (`kill -0`) or a BRACKETED pattern (`pgrep -f "[c]laude …"`) — a bare pattern matches its own probe/quoting shells (F-13).
4. **Retry only on confirmed-absent, under a lock.** Hold a per-run spawn flock across the spawn — `<log-root>/<runkey>-spawn.lock` for a worktree run (its log root is iso-scoped), `<iso-id>-<runkey>-spawn.lock` in the flat `.cursor/loops/` root for a `branch`/`none` run (`<runkey>` recurs across runs — locks are never shared across runs). The SHIPPED spawn wrapper (§8; canonical `## Backends`) holds this flock for you when passed `LOOP_SPAWN_LOCK` — a refusal prints `SPAWN_LOCK_HELD` on ITS stdout (exit 3, zero probe-log writes) for your ADOPT/collision disposition, never a probe-log line. A spawn attempt that LOOKS failed (tool-bubble timeout, missing confirmation) may still have succeeded: before ANY retry, probe for its effects — recorded identity live, role log created/growing, lock held. Lock held ⇒ ADOPT the lock-holder as the sole spawn ONLY when its recorded identity belongs to THIS run's iso-ID/ownership claim (verify + record it) — a foreign run's holder is a COLLISION to surface, never an adoption candidate; NEVER spawn beside a held lock. On duplicate suspicion, sole-count using THIS run's recorded identities only (bare process patterns false-positive against concurrent runs on the same machine) and kill the untracked extra. (Observed live 2026-07-24: bubble-timeout retries double-spawned twice — a 4-min unwatched ghost the first time; flock+ADOPT prevented occurrence three.)
