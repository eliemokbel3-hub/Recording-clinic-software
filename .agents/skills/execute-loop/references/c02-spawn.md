# Wake card detail, part 2 — sections 4 to 6: the spawn guard, spawn-prompt invariants, peer-orphan recovery
Previous: c01-role-and-wake.md. Next: c03-dispositions-and-records.md. Moved word for word from the wake card STICKY.md; this file has no headings of its own.

Contents, in order: section 4, the spawn guard, steps 1 to 9, with the peer launcher's recipe at step 8 and router mode at step 9; section 5, the spawn-prompt invariants, ten bullets; section 6, peer-orphan recovery, one paragraph, with the two-leg shape and verify-then-fix.

1. Look up the PRIOR executor's recorded identity — the shell id / PID you recorded at its spawn; never a `pgrep` pattern.
2. Verify THAT identity is dead: the recorded PID is gone, or the background shell reports completed/exited WITH THE ROLE'S OWN CODE. A quiet log or long silence is NOT dead — check, never assume. From v48.0, for a wrapper leg, NONE of these is a dead role by itself: a shell that ended (it holds the wrapper's TAIL — exit 5 `SPAWN_DETACHED`, exit 6 `SPAWN_LOST`, or a task the host ended say nothing about the role), a gone `wrapper_pid` (a wrapper killed outright leaves its role running), or a `<leg>.exit` file (it says the WRAPPER returned; a role can outlive it). The role-liveness reader decides: `python3 scripts/loop-watchdog.py tick --base "<abs base>"` (no `--act`) prints `legs=live:<n>,unknown:<n>,over:<n>` on this run's line. `live:0` is REQUIRED — any `live` leg is a role of the run still running: watch it (§3's waiting rules), NEVER spawn beside it. An `unknown` leg → pause for the operator, unless it is one already closed on their attestation (its `ROLE: end` on the log names `owner-dead`). The count reads the run's log folder (`<base>/.cursor/loops/<iso-id>`, or the journal's `log_root=`): on a run with NO run worktree (`isolation=branch|none` — leg files in the flat root) it is always zero and proves nothing — there take the CONSERVATIVE reading of EVERY file of the leg beside the probe log (`<leg>.live`, `<leg>.exit`, `<leg>.<n>.*`, by the `leg=` line inside), over only when each says so: an `.exit` reading `launched=no`; or (POSIX) `kill -0 <role_pid>` and `kill -0 -- -<role_pgid>` BOTH answering "No such process", and for a `.live` with no `.exit` the `wrapper_pid` too; or (Windows-native) an `.exit` reading `launched=yes`. Anything else is NOT over — another answer from `kill` (e.g. "Operation not permitted": a process is there), a `.live` with no `role_pid`, `launched=unknown`, any `.live` without `.exit` on a Windows-native host: watch what may be running, pause for the operator where it cannot be told (canonical: SKILL → loop step 1, invariant (ii)). And before the spawn, the stop's wake rule (§7): `mark=yes` on the `seat` line → the operator stopped this run — NO spawn, no resume.
3. Only on a confirmed-dead result, spawn the new executor and record its identity. Never a second `ROLE: start` for a phase while the prior shell is live. A live role that recorded an open gate is PAUSED, not hung — never kill it. Single-emitter ownership (DR-1): for wrapper-spawned roles the WRAPPER writes `ROLE: start` (from `LOOP_PHASE`/`LOOP_MODEL`/`LOOP_LEG`) — you mint a FRESH `LOOP_LEG` per activation (mint-fresh stays YOUR duty — a stateless wrapper cannot detect reuse; NEVER reuse a leg value within the run) and from v48.0 the WRAPPER writes the matching `ROLE: end` as well: you write the leg-bound `CONSUME` reusing that leg VERBATIM (`leg=<the LOOP_LEG value>`), and an end of your own only in the clean close of §3's Wrapper legs bullet (an end with no matching open activation is the end-without-start violation; a second end for the leg is refused); you NEVER author a `ROLE: start` for a wrapper-spawned role — a composer start beside the wrapper's is the duplicate-start violation. A composer-seat codex peer round on a run with a run worktree goes through the peer launcher (step 8), which writes the leg's start, its escape-check record, and its end itself — you write none of the three; the other non-wrapper activations (§3's Launcher legs bullet, "Where the hand route stays") get their lifecycle via `emit ROLE:start` / `emit ROLE:end`. Liveness probes use the recorded PID (`kill -0`) or a BRACKETED pattern (`pgrep -f "[c]laude …"`) — a bare pattern matches its own probe/quoting shells (F-13).
4. **Retry only on confirmed-absent, under a lock.** Hold a per-run spawn lock across the spawn — `<log-root>/<runkey>-spawn.lock` for a worktree run (its log root is iso-scoped), `<iso-id>-<runkey>-spawn.lock` in the flat `.cursor/loops/` root for a `branch`/`none` run (`<runkey>` recurs across runs — locks are never shared across runs). The SHIPPED spawn wrapper (§8; canonical `## Backends`) holds this lock for you when passed `LOOP_SPAWN_LOCK` — a refusal prints `SPAWN_LOCK_HELD` on ITS stdout (exit 3, zero probe-log writes) for your ADOPT/collision disposition, never a probe-log line. A spawn attempt that LOOKS failed (tool-bubble timeout, missing confirmation) may still have succeeded: before ANY retry, probe for its effects — recorded identity live, role log created/growing, lock held. Lock held ⇒ ADOPT the lock-holder as the sole spawn ONLY when its recorded identity belongs to THIS run's iso-ID/ownership claim (verify + record it) — a foreign run's holder is a COLLISION to surface, never an adoption candidate; NEVER spawn beside a held lock. On duplicate suspicion, sole-count using THIS run's recorded identities only (bare process patterns false-positive against concurrent runs on the same machine) and kill the untracked extra. (Observed live: bubble-timeout retries double-spawned twice — a 4-min unwatched ghost the first time; the lock + ADOPT prevented occurrence three.)
5. **Spawn and arming are ONE act.** The SAME message that starts a CLI role (its background shell on a `bg-shell` resolution; an `fg-wait` composer's spawn-and-wait is one act by construction) states steps 1–2's results (prior identity → dead-check result → new identity), configures the output/completion watch (the preflight-resolved Layer-1 surface, §3), arms the Layer-2 watcher (monitor by default — §3), and prints the `WATCH: armed` line. A spawn message without its armed line is an unwatched spawn — a violation even when the phase is expected to finish in seconds (a fast phase is not an exemption; an entire run without one `Wake:`/`WATCH:` artifact was observed live).
6. **Escape-check record — ONE per HEADLESS ACTIVATION, COMPUTED, never hand-typed (F-04).** Wrapper-spawned roles: the WRAPPER owns it (a failed pre-capture refuses the spawn; a failed post-capture folds to non-success — exit 3 wrote the `refused=capture-failure` record, exit 2 wrote NO record; the wrapper never claims a record it did not write). A launcher leg (step 8): the LAUNCHER runs both captures itself, through the helper, around its spawn — you run neither (the one exception is the POST of §3's clean close). EVERY other non-wrapper headless activation — each hand-route PEER round (§3's Launcher legs bullet, "Where the hand route stays"; `codex exec` spawns included — the run-6 uncovered-window class) and every inline fallback — brackets its spawn with the helper-twin PAIR: PRE `python3 scripts/loop-journal.py escape-check --run <runkey> --role <spawned role> --capture pre --leg <leg> --log-root <dir> --iso <this run's iso-id> --liveness <the resolved minutes|off> [--edit-surface worktree] [--allow-path 'worktree:<plan path>;worktree:<findings sidecar>'] --root base=/abs [--root <name>=/abs …]`; POST (after its exit — the SAME run/role/leg/root/edit-surface/allow-path tuple, adding only the output log) `python3 scripts/loop-journal.py escape-check --run <runkey> --role <spawned role> --capture post --leg <leg> --log-root <dir> --log <probe-log> <the same --iso/--liveness/--edit-surface/--allow-path> --root base=/abs [--root <name>=/abs …]` — the ONE emitted record carries computed digests, `result=`, `leg=`, and the `roots=` manifest binding EVERY canonical-baseline root (base + isolation worktree + every confirmed external read root — SKILL.md → `## Safety gates — the loop PAUSES, it never bypasses`); v33.0 (D4): executor/architect/delegate spawns declare `--edit-surface worktree` (wrapper `LOOP_EDIT_SURFACE`), a PEER declares no edit surface and gets `--allow-path` for its plan file + `findings-*.md` sidecar ONLY (wrapper `LOOP_ALLOW_PATH`) — its only legal writes; a pre/post edit-surface or allow-path mismatch writes the exit-3 `refused=capture-failure … detail="edit-surface/allow-path mismatch between pre and post"` record. The root set never shrinks mid-run, and NO peer activation window goes unbracketed.
7. **Consume the wrapper's evidence after every wrapper spawn closes:** read its `escape-check` `result=` and `exit-census` `children=` from the probe log. VERDICT (`result=` stays `clean|dirty`, computed over every root EXCEPT the declared edit surface): `result=clean` (an executor's `edit_surface=worktree:changed` beside it is the normal build exit — its own worktree product is never an escape) → proceed; `result=dirty` WITHOUT `attributed=` (or a `refused=capture-failure` record) → MUST-PAUSE in EVERY gate mode; `result=dirty attributed=<foreign iso> attributed_age=<min>` (a base-only change claimed by a LIVE concurrent run — its marker `-active`, no `.complete-*` sibling, `checkout=` equal to every changed root, a genuine probe log younger than 2× liveness) → under `gates=executor` AUTO-PROCEED act-and-inform: emit the evidence `CLASSIFY:` then the pair `emit OWNERSHIP:auto-disposition … --epoch "<activation id>" key=escape-attributed-<leg> detail="<the attribution + why proceeding>"` (a leg-qualified topology key — two attributed exits in one phase are two pending members; `class=auto-disposition`, mode COMPUTED `queued` → the phase batch); under `strict`/`fix-biased` SURFACE with the attribution in the ask. Attribution is KNOWN-WEAK (a live concurrent run, not proof of authorship): this run's OWN cwd=base violation could be laundered as foreign, which is why every spawned role's cwd is the worktree (§5) and `/retro` audits every `attributed=` record. A `dirty` peer round outside its allowed plan/sidecar paths stays `dirty` (a peer has no edit surface). `children=` > 0 → an anomaly consume (survivors are YOUR disposition — the wrapper never kills). A launcher leg (step 8) is read the same way from its escape-check record (`result=`, `attributed=`), and an `escape=` other than `0` on the launcher's `PEER_LAUNCH_EXIT` line is the same MUST-PAUSE as a capture failure, in EVERY gate mode; a `refused=` escape-check record found for the leg stays one.
8. **The codex peer launcher — the route for EVERY composer-seat codex peer round on a run with a run worktree.** It runs ONE round and writes that round's records itself, through the helper, in a fixed order: the keyed `ROLE: start` (marked `via=launcher`), the escape-check record, and the `ROLE: end`. It serves runs with a run worktree ONLY (`isolation=worktree` — the tools and the logs on the base side, the peer in the worktree); it refuses any other topology, and those rounds keep the hand route (§3's Launcher legs bullet). Mint a FRESH leg, take the ref snapshot (§1), then — from the BASE checkout (the launcher refuses when it sits inside the worktree), in a background shell — set every parameter in the environment and run the bare command (an env-prefixed command does not match an exact grant):

   ```bash
   export LOOP_CODEX_BIN="<abs codex binary>"
   export LOOP_CWD="<abs run worktree>"
   export LOOP_PROBE_LOG="<probe-log>"
   export LOOP_PEER_LOG="<abs peer log>"
   export LOOP_IDENTITY_FILE="<abs identity file>"
   export LOOP_PROMPT_FILE="<abs prompt file>"
   export LOOP_PLAN="<abs worktree plan>"
   export LOOP_RUNKEY=<runkey>
   export LOOP_PHASE=<phase>
   export LOOP_LEG=<leg>
   export LOOP_MODEL=<model slug>
   export LOOP_ESCAPE_ROOTS='base=<abs base>;worktree=<abs run worktree>'
   export LOOP_PASS=<pass id>
   export LOOP_PEER_ROUND=<k>
   export LOOP_CAP=<N>
   export LOOP_EFFORT=<level>
   export LOOP_ALLOW_PATH='worktree:<plan path>;worktree:<findings sidecar>'
   export LOOP_ISO=<iso-id>
   export LOOP_LIVENESS=<minutes|off>
   export LOOP_ROUTE_BIN="<the realpath resolved at preflight — under router=on only>"
   python3 -I scripts/loop-peer-launcher.py
   ```

   `LOOP_CODEX_BIN` is the absolute path `command -v codex` prints — resolve it once. The first fifteen lines are REQUIRED (the three pass keys — §7 — all of them: a launch with any missing is refused). `LOOP_PROBE_LOG` is the phase's existing probe log; `LOOP_PEER_LOG` and `LOOP_IDENTITY_FILE` sit in the run's base-side log folder, and the identity file is a FRESH path per launch (an existing one is refused); `LOOP_PLAN` is the worktree plan copy; `LOOP_ESCAPE_ROOTS` is the run's FULL root set — the one its wrapper spawns pass. The last five lines are OPTIONAL: omit `LOOP_EFFORT` when effort is inherit; `LOOP_ALLOW_PATH` (the plan, plus a findings sidecar when there is one — without it the peer's own round reads `dirty`), `LOOP_ISO`, and `LOOP_LIVENESS` are the values step 6's pair carries; `LOOP_ROUTE_BIN` (v41.0 router mode) is set under `router=on` ONLY — the realpath of `claude-switch-route` resolved at preflight, quoted — and the launcher then asks the router for the round's `CODEX_HOME` itself (it requires `LOOP_ISO`; no answer keeps the inherited home; the EFFECTIVE home rides the identity file as `codex_home=` beside `route_run=` / `route_phase=`); omit the line on an unrouted run, under the partial `on` Preflight step 15 names (its codex bogus-home or inherited-home check failed — codex rounds unrouted), and for the rest of a phase after a last-resort round ran without it (step 9). `LOOP_EDIT_SURFACE` must NOT be set — a peer declares no edit surface, and the launcher refuses it. The prompt file carries `/peer-loop`'s structural invariant (e) (the sandbox suites line: the suites the sandboxed peer must not run, and that you re-run them outside the sandbox and paste their results); nothing new is exported for it — the launcher owns the child's `XDG_RUNTIME_DIR` (a private per-launch dir it creates and removes; its docstring). The launcher takes no argument. Do NOT tee or redirect its output into the peer log: the launcher appends codex's output there itself, and its own standard output is the status lines. Arm both wake layers in the same message (step 5) — the launcher's shell and its recorded pid for the exit, the peer log as the log the liveness layer watches grow. From the launch to the launcher's exit you do NOT edit the plan file — the peer appends its round there — and you re-read the plan after the exit before any edit (`/peer-loop` step 2). Its standard output carries ONLY three line shapes (codex's own output goes to the peer log): `PEER_LAUNCH_REFUSED check=<token> detail="<text>"` — printed alone, exit 2, the probe log unchanged; `PEER_LAUNCH_START leg=<leg> pass=<pass> peer_round=<k> cap=<n> baseline=<N> pid=<pid> pgid=<pgid> peer_log=<path>` — once codex is running; and, last, `PEER_LAUNCH_EXIT rc=<codex rc|none> start=<written|uncertain> round=<new:<M>|none|unknown> escape=<helper exit code|none> end=<written|failed|none> group=<clean|killed|none> tools=<ok|changed> duration=<s> leg=<leg>`. Exit codes: `0` — codex exited 0, a new round was appended, the post capture and the end call each exited 0, and the tools were unchanged; `2` — refused; `1` — anything else. The lines are a wake surface, never the record: the baseline and the tool ids ride the start record, and the child's identity (`launcher_pid=`, `codex_pid=`, `pgid=`) is recorded in the identity file. An exit code is never proof of a record — after the launcher is dead, §3's Launcher legs bullet decides what the leg is. Before relying on the launcher, verify its bytes (§8). The script's own header is the code-side contract.
9. **Router mode (only while the `Loop config:` line carries `router=on`; otherwise nothing here applies).** On EVERY wrapper spawn — fresh, respawn, resume; peers included — set `LOOP_ROUTE_BIN=<the realpath resolved at Preflight step 15, re-resolved on every resume>` beside `LOOP_IDENTITY_FILE` and `LOOP_PROFILE_DIR=<that role's profile_dir — its FALLBACK>` (§8 names the variable; the wrapper owns the call, the answer rule, and its refusals — a refusal is YOUR parameter bug, exit 2, no spawn), EXCEPT a pinned leg: a role whose identity record carries no `route_run=` was pinned by a manual Switch account or a last-resort leg — keep `LOOP_ROUTE_BIN` OFF and `LOOP_PROFILE_DIR` the pinned folder for the rest of the phase; the next phase routes again (an architect's `profile-switch` leg re-runs Preflight step 5 in the new folder BEFORE the respawn when `agent_loc=profile` — v43.0, the definition moves with the profile; under `router=on` `agent_loc=project` is forced and nothing moves — SKILL → Preflight step 5). On a resume `LOOP_PROFILE_DIR` is the folder that holds the transcript, never the `Loop config:` value — on an architect-mode run the composer's RETAINED verified root for the role, the identity record's `profile_dir=` read back as data and required EQUAL to it (a disagreement → the three-option pause, never a launch and never a trusted root — SKILL → loop step 1's resume-root rule, v43.0; read THERE); on every other run the record's `profile_dir=` (for a role with a profile in `Loop config:`; a role with none passes NO `LOOP_PROFILE_DIR` on its resume — from v47.0 the record names the launch folder on every spawn, the ambient one included) — AND, on a routed identity (`route_run=` present), `LOOP_PHASE` is its `route_phase=`, byte for byte (a resumed session's phase identity never changes; a re-worded phase is the `resume-mismatch` cause). **The resume pin:** you still pass the holder you know; the wrapper then FINDS the transcript's holder among that folder, the router's answer, and the ambient folder and starts the role on the newest copy — `SPAWN_WARN check=resume-pin detail="<holder>"` when that is not the folder you passed, `SPAWN_WARN check=resume-pin-stale detail="…"` for older copies elsewhere (journal both as `ADOPT:`), and `SPAWN_REFUSED check=resume-pin`, exit 2 with no child, when no candidate holds the transcript or one could not be searched: read the refusal, fix the folder (the transfer recipe, unchanged), never retry blind (SKILL → Backends, the spawn wrapper) — print the record's `session=`, `profile_dir=`, `route_run=`, `route_phase=` lines first; copy `session=`, `route_run=`, and `route_phase=` from them, and compare `profile_dir=` as the rule says; a pinned identity keeps today's phase with `LOOP_ROUTE_BIN` off, its FIRST pinned resume carrying the routed record's `route_phase=` read before the spawn; a `resume-mismatch` on a resume whose `LOOP_PHASE` already equals the record's `route_phase=` pins the role for the phase (the rule and the pin: SKILL → Visibility + run-state, the Resume contract's routed-resume phase rule — read THERE). Journal the wrapper's `SPAWN_ROUTE dir="…" via=pick|binding` or `SPAWN_WARN check=router detail="<word>"` stdout line as `ADOPT:` — BOTH `SPAWN_WARN` lines when two print (the `check=route-skipped` line right after the first) — no answer is never a stop. A composer-seat codex round: the recipe's `LOOP_ROUTE_BIN` line (step 8) — omitted for the rest of the phase once a last-resort round ran without it. A ROUTED role (its identity record carries `route_run=`) DEAD on a limit is re-picked — three per run on ONE counter for every role; `profile-fallback=` the Claude roles' last resort, the launcher's inherited home the codex peer's only when it differs from the failed home (else the pause; and `--failed` carries its `codex_home=` only when absolute); a pinned role goes to the pause, no re-pick — every step of it is SKILL → `## Usage-exhaustion recovery (claude pools)`, the router branch (read THERE, never from memory). The release of the run's bindings at the FINAL close only: SKILL → Run isolation → Mechanical close enforcement (`/close-run` performs it; never at a group close, a park, or a pause).

Under `isolation=worktree` EVERY spawned role's cwd is the WORKTREE — peers included (D4's invariant; a peer round pinned to base produced the only base-side escape dirt in the field) — and every wrapper spawn carries `LOOP_ISO=<this run's iso-id>` + `LOOP_LIVENESS=<the resolved minutes|off>` (§8), `LOOP_EDIT_SURFACE=worktree` for executor/architect/delegate, `LOOP_ALLOW_PATH` (plan + sidecar) for a peer — and, under `router=on`, `LOOP_ROUTE_BIN` + `LOOP_IDENTITY_FILE` + `LOOP_PROFILE_DIR` on every wrapper spawn except a pinned leg (§4 step 9) — on a resume, `LOOP_PROFILE_DIR` and, on a routed identity, `LOOP_PHASE` copied from the identity record (the routed-resume phase rule, §4 step 9 by pointer).

- Peer topology: the COMPOSER SEAT is the default — YOU drive `/peer-loop`, spawning each peer round yourself and routing findings over §6's two-leg resume shape (run-evidenced: 0/9 executor-seat rounds completed vs 7/7 composer-seat; it is the SEAT, not the foregrounding). Every peer spawn prompt carries `/peer-loop`'s structural read-scope steering: pin the diff + explicit file list as the review surface, name closed historical rounds not-reading-material, frame security-shaped/grammar-quoting content as prose-to-review, treat records as current AS OF their closing round (finishing seat writes Last-reviewed; fix-refreshed currency is not a finding — invariant (d), v32.5). Peer-round wait shape: where the run resolved `layer1=bg-shell` and delivery is not `fg`, prefer the composer-owned background shell + the preflight-resolved Layer-2 mechanism for the round (the resolved `Wake:` line stays the mode authority for BOTH layers — a preference, never a mandate; a monitor only where `layer2=monitor` resolved). Where a foreground wait applies, your OWN composer-seat child waits are CHUNKED bounded polls (up to min(liveness interval, ~10 min) per call — ~10 min flat under liveness OFF; spawned headless roles keep ≤ ~2min) with a `[<runkey>]` heartbeat line at least once per liveness interval (liveness OFF: at least every ~10 minutes of waiting), carrying `delivery=<resolved>` whenever the run has a delivery resolution (chat format only) — a multi-tens-of-minutes silent wait over a live round is a violation (observed live). On a launcher leg (§4 step 8) both wake layers watch the LAUNCHER — its shell and its recorded pid — and a child's death is not an exit event; the child's recorded identity is for the clean close and for the wait on an orphaned group, and a launcher leg judged hung is a PAUSE — you kill nothing on it (§3's Launcher legs bullet).
- The two exit rules a headless role cannot infer: the role NEVER ends its turn or writes its final message while anything it started is still running — a child process (opt-in peer rounds first), a shell job, or a command or subagent the harness runs in the background — because a headless role may never be woken again ("I'll continue when the completion notification arrives" is a stop, not a wait; a headless session's children die at turn end): it runs the command in the foreground or waits in the same turn — and a wait is CHUNKED bounded polls (≤ ~2min per call), never one capped tool call (a single 600s-capped Bash wait died under a live peer and orphaned the round, observed); and the ATOMIC final step: before the final message, the role makes ONE validated declaration call — `python3 scripts/loop-journal.py emit VERIFY_OK --run <runkey> --role <role> --log <probe-log> children=<n>` with its OWN declared still-live child count (the tool owns the FORMAT, the role supplies the count — r2-B2; the wrapper's `OWNERSHIP: exit-census` is the independent observed cross-check that catches a false declaration) — any live child (`n` > 0) means keep waiting, never exit — and the literal last output line is the `ROLE: handoff` exit sentinel. (Defense-in-depth: §3's exit-classify routing is the mechanical guard when this prompt rule fails — it failed 3× live.)
- Plain shapes: a granted command is run as the plain single command the grant list shows, in the grant's own spelling — a relative path where the grant has one (`python3 scripts/loop-journal.py emit …`, as the exit declaration above is written), an absolute path only where the grant or the prompt gives one (the literal log path below; a program the Grants line proposed in its absolute-path shape) — since a `cd <dir> &&` prefix, a pipe, a loop, or a shell variable makes it a different shape that is refused, and the role does not try variants: it uses the granted shape or hands the step back once.
- The literal log path: EVERY spawn prompt carries the probe log's absolute path as literal text, with the line "wherever the footer says `$LOOP_PROBE_LOG`, type this path" — the wrapper and its footer are unchanged (SKILL → loop step 1; the Spawn wrapper paragraph in Backends).
- Every artifact timestamp the role writes (`ROLE: handoff` included) is a real clock read — `date -Iseconds`, local ISO with offset — never composed, rounded, future-dated, or UTC-`Z` (fabricated handoff timestamps observed live force `/retro` onto composer lines).
- The executor NEVER commits or advances any repository ref — commit authority is composer-seat-only (§1); the composer's commit/ref/reflog boundary snapshot fails the phase on any executor-side commit, even one hidden by a reset.
- MUST-PAUSE record-and-end: a spawned executor records an open gate in the plan handoff note + its final message, then ENDS; you relay it to the user.
- The operator-facing final brief is an ARTIFACT: the executor writes its full assessment/handoff brief into the plan handoff note (or `<log-root>/<runkey>-handoff.md` when it outgrows the note) — the composer relays that artifact verbatim (§1 relay fidelity). A brief that exists only inside the session's final message risks lossy relay.

If an opt-in executor dies mid-`/peer-loop` (crash, limit-death, orphaned round): YOU resume the pass from the plan's Review Findings Log — continue round numbering from the last logged round, close any open round block, verify/route outstanding findings per that round's `Source:`. Do it immediately — never ask "want me to take over?", never restart from round 1, never mark an interrupted round converged.
