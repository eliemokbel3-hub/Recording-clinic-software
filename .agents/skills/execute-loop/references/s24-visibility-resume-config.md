- **Run-state persistence.** After each meaningful step, update the plan's `Current State / Handoff Note` with the current phase, the last completed step, the immediate next action, open blockers, and the last sync — so the composer survives a compaction or restart and resumes from disk, not memory (the full recovery sequence is the **Resume contract** bullet below). The next-action line must reflect the ACTUAL state at write time — never leave a stale "on resume: `/review-loop` → `/peer-loop`" standing after those have partially run (observed live: only the log had the truth, and a composer trusting the plan would have re-run a converged review). Under `isolation=worktree`, these run-state writes — this handoff-note update and the `Loop config:` line below — target the AUTHORITATIVE worktree plan copy from creation onward, never the retained base copy (see **Run isolation (worktree-per-run)**). `/execute-loop` adds no new plan section; it reuses the existing handoff note.
- **Sticky rehydrate (the every-wake companion card — REQUIRED composer duty).** The companion card `STICKY.md` (shipped beside this skill in the same directory, both surfaces) is the loop composer's every-wake rehydrate card. At run start (immediately after preflight, before the phase-1 spawn), on EVERY wake (a Layer-1 shell notification, a sentinel firing, a monitor return, or a user message that resumes orchestration), and on any resume: read the card plus the plan's `Current State / Handoff Note` (`Loop config:` included) BEFORE acting on the wake, then state — to yourself, and in the `[<runkey>]` status line where one is due — the runkey, current phase, and immediate next action. Acting on a wake without the rehydrate is a contract violation (the summarization/context-loss failure class this card exists to prevent — a composer orchestrating from remembered intent — was run-proven across the 2026-07-24/25 and 2026-07-25/26 observed harness runs). On suspected context loss — the composer cannot state runkey/phase/next action; the inability IS the detector — run the **Resume contract** below with ONE modification: its step (1) run-mechanics re-read is satisfied by re-reading the card plus the specific canonical sections it points into, the bounded card replacing the whole-file re-read (read full sections only when the context budget clearly allows).
