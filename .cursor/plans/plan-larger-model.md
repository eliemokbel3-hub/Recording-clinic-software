### Honest forecast
Written before any measurement and not tuned toward:
- **No candidate may clear the bar, or none may beat `medium`.** `large-v3` on CPU int8 is roughly 2–3× `medium`'s work (RTF likely 0.8–1.5 by the app's call: WARNING or FAIL). `large-v3-turbo` keeps large-v3's encoder with a 4-layer decoder, `distil-large-v3` a 2-layer one — both plausibly under 1.0 here, unmeasured. If none is eligible, or none beats `medium` under D1, **the plan stops at Task 0.6 with no model change**, and that is the recorded finding.
- **A larger model may not fix the two classes that failed.** A letter abbreviation and a unit are exactly where a bigger decoder can be more confident and still wrong; a confidently misheard word on an unmarked line fails rule v3's predicates whatever the model. The blind `heldout-5` decides; `heldout-4`'s two facts are evidence only (seen).
- **Marks move with the model.** The guard's constants and the 0.60 threshold were measured on `medium`; a more confident model marks less, which can move a misheard fact from R1 (excusable) to "wrong without a mark" (fails). D3/D4 measure this before anything is decided.
- **Word alignment is poorer on a 2- or 4-layer decoder.** `assign_words_to_segments` splits a window's words across VAD segments by word stamps and `mark_segment_words` reads word probabilities, so misassigned words move lines between speakers and shift `low_confidence_source` marks — a failure that shows as attribution, boundary and load changes, not WER (`attribute_speakers` itself reads embeddings, not stamps). A conversion without `alignment_heads` fails at `find_alignment`; the benchmark's `word_timestamps=True` call is that check (Task 0.3).
- **Near-silent windows.** large-v3's known mode is a repeated or invented phrase over near-silence; windows are VAD-packed so silence is mostly excluded, `compression_ratio_threshold` stays at faster-whisper's default, and D3's measurement set carries silence and noise beds. Reported, never tuned.
- **Live transcription loses margin.** The live worker fails `FELL_BEHIND` when more than two packed windows wait or more than 90 s of audio is queued (model load included); the desktop then shows nothing until Finish and the WHOLE recording is re-transcribed in batch. At an app-shape RTF of 0.9 a 15-minute consultation waits about 14 minutes for its note (about 8 today), and the first live line appears later (load + first window ≈ 50–70 s against ≈ 35–45 s). The eligibility bar is the app's call (D1), and P.2 measures a long mock.
- **Memory.** The language model stays resident after any prose note (~2.5 GiB), so the app's real peak is Whisper + 2.5 GiB; `large-v3` at ~3.5 GiB alone is ~6 GiB together on this 16 GB computer — fine, but stated.
- A PASS is an outcome to report, never a target.

## Design Decisions

### D1 — The candidates and the selection rule (decided 2026-11-04 before any download)
Candidates: External / API Findings. `setup-models.py` accepts `--only <name>` only for an entry already in `WHISPER_CANDIDATES` and fetches exactly that revision, so Task 0.2 writes the SHAs as the pins first; the fetch succeeding at that revision confirms them, and the per-file SHA-256s are recorded from the fetched files (the manifest carries them for the chosen one). Measurement order: `large-v3-turbo`, `distil-large-v3`, `large-v3` (cheapest first); every ELIGIBLE candidate is measured in full — rule 2 has no early stop.

**The selection rule (mechanical; applied once at Task 0.6 to Tasks 0.3–0.5):**
0. *Completeness (a premise, not a criterion):* a model's five-set measurement is selection evidence only when EVERY expected encounter of every set has status `measured` — none `role_unresolved` (an unresolved clinician yields no fact metrics, `validation.py:2984-2992`) and none `error` (`:3075-3080`) — and the runner printed no `[error]` line — all readable from the report itself: the run-information line's `Encounters: N; set-level errors: N` (`validation.py:3324`), the per-encounter status column (`:3432`) and the table's `TOTAL | N measured` (`:3462`); an unmeasured encounter adds nothing to the totals (`:3365-3367` prints `-` cells), so an incomplete run would look BETTER on rules 1 (d) and 2. An incomplete run is invalid evidence for that model: its cause is a finding, and the run is repeated before D1 applies (a quality failure — a wrong fact, a failed verdict — is a legitimate measured result and never a reason to repeat). Run 7's `medium` reports hold no unmeasured encounter (checked 2026-11-04), so the premise holds for the comparison.
1. *Eligibility:* (a) **app-shape RTF < 1.0** — the benchmark's new `--app-shape` timing (the provider's own call: primer, `language="en"`, `beam_size=5`, `word_timestamps=True`, `condition_on_previous_text=False`) over the panel's 53 s sample cut by the app's own packer (`pack_transcription_windows`, `TRANSCRIBE_WINDOW_SECONDS` 30) into production-sized windows, ONE provider call per window with the primer supplied fresh each call exactly as the app does (`transcription.py:1005`, `:1065`; a single call over the whole sample seeds the primer once and understates the cost), RTF = summed decode time / summed audio, median of three idle runs; the panel's own RTF is recorded beside it, not decisive (the practitioner's decision 2026-11-04, refining "RTF < 1.0": the bar means the live view keeps up); (b) peak working set ≤ 4096 MiB and load ≤ 30 s, read from the benchmark table's `peak MiB` / `load s` columns (they carry no status; measured alone — add ~2.5 GiB for the resident language model); (c) the mel assertion passes and `word_timestamps=True` returns words (alignment heads present); (d) **silent material omissions summed over the five seen sets ≤ `medium`'s** (the practitioner's decision 2026-11-04: the distil family's known failure is dropped clauses, which land here, not in rule 2).
2. *Quality, among the eligible:* fewest material facts with verdict **`wrong`** summed over the five seen sets (NOT `material_wrong`, which also counts `wrongly_present` — the R3 class — `validation.py:927-933`); tie → lowest pooled canonical word error rate; tie → lowest app-shape RTF.
3. *Floor:* the winner must beat `medium` on rule 2's first count. Equal or worse → no model changes (Task 0.6 "No change"; Flow 4).
4. Nothing else is read for the choice — not which of `h4-01/f5` / `h4-07/f0` a candidate gets right (reported as evidence, ids only), not R2 or R3, not the primer's token count (Task 0.3's check, not a discriminator: the tokenizer is shared).

Alternatives rejected: one candidate only (the practitioner chose all three); the panel's RTF as the bar (understates the app's call); `material_wrong` as the count (reads R3); the token count as eligibility (a no-op).
