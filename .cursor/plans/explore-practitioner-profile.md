## Key Findings

### Files / Symbols Involved (code-verified)

**Speaker labelling (the thing enrolment replaces the guess in)**
- `desktop/src/scribe_desktop/transcription.py`
  - `_segment_embedding(pcm, np, *, sample_rate=16000, cepstral_mean_normalisation=True)` — 24 mel-band log powers + a low-band spectral centroid averaged over 25 ms Hann windows, mel part cepstral-mean-normalised per segment (Task 2.1). numpy only, no model.
  - `_kmeans_two(features, np)` (10 seeded restarts, 30 iterations) and `_cluster_embeddings(embeddings, np) -> list[str]` — z-scores the features, 2-means, first segment is ALWAYS `SPEAKER_1`, degenerate (identical features / all one label) → every segment `SPEAKER_1`.
  - `label_speakers(segment_pcms, *, sample_rate, cepstral_mean_normalisation)` — whole-list wrapper (tests + the 2.3 harness). `transcribe_session` (`:886`) does NOT call it: it embeds each VAD segment inline per ~30 s window to bound plaintext (`:960-990`) and clusters once at the end; the degenerate policy is duplicated at both sites with a "change together" comment (round 42 LOW-011).
  - `SPEAKER_1 = "speaker_1"`, `SPEAKER_2 = "speaker_2"`; `TranscriptSegment.speaker: str` is a free string; `TranscriptDocument` carries `model_name`, `sample_rate`, `transcript_segments`.
  - Pinned behaviours (`tests/test_transcription.py:455-511, 700, 865`): single/identical segments → one speaker; two distinct voices alternate; first segment is speaker one; empty PCM degrades; gain shift leaves the embedding unchanged; labels survive batching.
- `desktop/src/scribe_desktop/note.py`
  - `speaker_role(document) -> SpeakerRolePreselection(preselected_clinician_speaker: str | None, margin, speaker_evidence)` (`:976`) — pure heuristic: question rate 0.60, first speaker 0.25, talk-time share 0.15; `None` for <2 clusters or a tie within `_ROLE_TIE_EPSILON`. Tests in `tests/test_note.py` pin: question-asker preselected, first speaker breaks symmetry, merged cluster preselects nothing, "the result is not itself a speaker label".
  - The confirmed-role guard (`:1783-1795`): `compose_draft(..., clinician_speaker=...)` must receive the CONFIRMED role; passing a preselection requires writing `.preselected_clinician_speaker` in plain sight. `CLINICIAN_OWNED_SECTIONS` populate only from the confirmed clinician's non-question utterances.
- `desktop/src/scribe_desktop/ui/transcript.py`
  - `_populate_generation_controls` (`:235`) calls `speaker_role(document)`, renders one `QRadioButton` per speaker from `models.speaker_quotations(document)` with a " (suggested)" marker; NONE pre-checked (confirmation mandatory). `generate()` (`:394`) takes `controller.begin_generation()` and calls `self._note_generator_factory(clinician_speaker=role, template_profile_id, prefill_id)` on a `TaskThread`.
- `desktop/src/scribe_desktop/speaker_eval.py` (Task 2.3a harness) — runs the SHIPPED `transcribe_session` in a temporary DPAPI-wrapped store; `cluster_metrics(predicted, truths)`, `role_outcome(...)` scores `speaker_role`'s preselection against Audacity role labels; the "before" condition re-embeds with CMN off. Results text-free by construction. An enrolment condition is a NEW condition + a new role outcome (enrolled classification), not a change to the existing two.

**Note routing (the thing the cue file parameterises)**
- `note.py` `_RAW_SECTION_CUES` (`:729-841`) — 17 sections × phrase tuples, normalised at import into `DEFAULT_SECTION_CUES` via `content_tokens`; `ExtractiveNoteProvider(cues=DEFAULT_SECTION_CUES)` (`:1067`), `_route` = first section in `request.section_keys` order whose cue is a contiguous token run (`_contains_phrase`, `:871`); clinician-owned sections skipped for non-clinician or question utterances; `provider_name = "extractive-v1"`. `note_check.py:140-146` records the cue lists as a FIRST CUT, not clinical evidence.
- `ui/models.py` `build_note_generator(..., config_root=None, provider_factory=ExtractiveNoteProvider)` (`:751-786`) — the ONLY production construction site: `load_note_config(config_root)` then `compose_draft(document, config, provider_factory(), ...)`. The provider is built WITHOUT the config, so config-supplied cues need `provider_factory` to receive `config` (a one-site change).
- `note_config.py` — precedence (module docstring `:29-50`): per-file WHOLE-FILE replacement, no deep merge; absent user file → shipped default (`config_defaults/<name>.json` via `importlib.resources`); an existing-but-unreadable/malformed user file raises (`_read_config_blob` `:771`). `NoteConfig(template_profiles, autofill_rules, prefill_templates)` is frozen, `extra="forbid"`; `to_bytes()` = `model_dump_json()`; `config_digest()` = `sha256-v1` over it, carried by `GeneratedNote`/`NoteRequest`/proposals. `*File` models carry `schema_version: Literal[1]`. Text validators: `_TriggerText` (≤200 chars, no control/format chars), duplicate-trigger detection under `content_tokens`. A fourth field changes every digest (by design: the digest identifies the content that drove a run) and no persisted artifact embeds a `NoteConfig`, so no migration.
- `note_fill.py` — `_first_phrase_match` / `content_tokens` are the same matching primitive autofill and prefill use.

### Codebase Integration Notes
- Enrolment output must NOT be written into `TranscriptSegment.speaker` as "practitioner": the role-confirmation design, the "result is not itself a speaker label" pin and the lying-speaker-field check (`test_note_check.py`) all assume opaque cluster labels plus a separate confirmed role. The clean seam is `speaker_role`: an enrolment MATCH becomes a fourth, dominant evidence signal (or a separate `EnrolledRoleEvidence` consumed by the same preselection), the radios keep " (suggested)", confirmation stays mandatory.
- Segment classification needs per-segment embeddings from the NEW model inside `transcribe_session`'s windowed loop (same place the spectral embedding is computed) so the plaintext bound is unchanged; the practitioner-vs-other split then replaces (or precedes) 2-means: practitioner segments get one label, the remaining segments are clustered among themselves (2-means today; estimated k later = D-S1).
- The cue file's provider injection is one site (`build_note_generator`'s `provider_factory`), plus `compose_draft` callers in tests that pass a bare `ExtractiveNoteProvider()` (the default cues stay the default, so those tests keep passing).
- `speaker_eval.py` gains an "enrolled" condition that needs a practitioner embedding for the harness run — derivable from the recording's own `clinician`-labelled spans (leave-one-out) or from a separate enrolment WAV; the harness contract (text-free, temp store, fail-closed teardown) is unchanged.
- No existing settings/persistence surface: the profile store is new (`%LOCALAPPDATA%\ClinikoScribe\profile\`), mirroring session custody (`key.dpapi` + an AES-GCM blob), and the consent record lives inside it.

### Key Design Decisions
- **Enrolment is evidence for the existing confirmation, not a new label.** Segments still carry opaque cluster labels; the practitioner match feeds `speaker_role` as a dominant signal. Rejected: a `practitioner` label written by the pipeline (breaks three pinned guards and the confirm-first control) and auto-confirming the role.
- **Practitioner-vs-other first, then cluster the rest.** With a profile present the pipeline classifies each segment against the enrolled vector and 2-means only the non-practitioner segments; without a profile the current path runs unchanged (no behaviour change until the practitioner enrols). Rejected: k-estimation as the first step (D-S1 stays deferred).
- **The profile store mirrors session custody, not config.** DPAPI-wrapped key + AES-GCM blob under `profile\`; deletion is key deletion; the embedding never lives in plaintext config (it is biometric). The consent record (timestamp, consent-text version) is stored inside the encrypted blob and in no log. Rejected: plaintext JSON next to the config files.
- **Cue file semantics = whole-file replacement, like the other three.** The shipped defaults become a real file the practitioner (or piece 3) edits; the loader's stated rationale ("merge semantics are where never-partially-applies goes to die") is kept. Rejected: an additive user file merged over defaults (friendlier to hand-edit, but a second precedence rule). Practitioner-confirmed 2026-09-05: whole-file.
- **Cues enter the config digest.** Every note is bound to the cue set that routed it, so a changed cue file is a changed `config_digest`, exactly as for autofill rules. Rejected: cues as a provider constructor argument outside the digest.
- **Enrolment capture bypasses the session store by construction.** A dedicated short capture through `CaptureBackend` into memory, embedded, then released; nothing on disk but the encrypted vector. Rejected: reusing `SessionController.start` (would create a session store and a recoverable audio artifact).
- **Learning is propose-then-approve, practitioner utterances only.** The eligibility check is structural (the utterance must be attributed to the confirmed clinician), the stored artefact is a phrase in the practitioner's own cue file, and the UI shows exactly what will be saved. Rejected: mining patterns from declined/moved lines silently.
- **Sequencing: enrolment → cue file → learning, with the gate run paused (practitioner-decided 2026-09-05).** Building enrolment before the gate avoids recording a set now and re-recording it once attribution changes; the rubric is untouched. Rejected: cue file first with an early gate run (would need a second recording set to measure enrolment).
- **Recording before enrolment stays allowed.** With no profile the pipeline runs exactly as today (the heuristic suggestion), so shipping enrolment changes nothing for a practitioner who skips it; the first-run Practitioner surface asks for enrolment and consent but does not block recording. Rejected: mandatory enrolment before any recording (blocks a practitioner whose microphone or model setup is incomplete, for no safety gain since the role is confirmed by hand either way). Flagged for the plan as a decision the practitioner may harden later.
- **Model candidate verification is a practitioner-run step.** The plan carries an early task in which the practitioner runs `scripts/setup-models.py --only <speaker-model>` from a normal terminal to fetch the SHA-pinned candidate before the enrolment build starts (practitioner-confirmed 2026-09-05).
- **Executor-tier concern for `/create-plan` Step 0:** premium-only throughout — DPAPI custody, a biometric artefact, the windowed plaintext bound in `transcribe_session`, the confirm-first guards, and the security docs are exactly the surfaces where the project's review history shows fast/medium executors over-claim.
