# Validation set inputs (pilot plan Phase 2)

- `scripts/` — 50 invented synthetic encounter scripts (`<id>.json`), voiced by three installed Windows voices (slots 0, 1 and 2; the patient of `syn-41` to `syn-50` is slot 1, the third voice). `scripts\build-validation-set.py` speaks them into a set folder; keep that folder outside this repository.
- `config/` — the note config the scripts are written against: the shipped defaults plus three autofill rules that `syn-07`, `syn-08` and `syn-09` trigger on purpose, and since 2026-10-09 the practitioner's own `section_cues.json` (26 phrases, written fresh and never copied from the app — rule v1's call 1), which replaces the shipped cue file; since 0.3.1 routing tries its phrases first and the shipped cues only for a line they route nowhere (`docs/testing/validation-harness.md`). Pass it as `--config validation\config`.
- `heldout/` — (2026-10-13, validation-pass plan Task 0.9) 22 invented synthetic scripts `hld-01` to `hld-22` for the next-patient boundary, the self-correction carry and spoken uncertainty, written by an author who had not seen the phrase lists those features use; their expected transcript-level outcomes are `desktop/tests/fixtures/heldout_transcripts.py`. A held-out check: never tuned to, and never edited to make a run pass. Same voices and builder as `scripts/` (slot 1 voices the third role: the next or previous patient, a partner or the receptionist).
- `heldout-2/` — (2026-10-23, validation-run6 plan Task 0.10) 22 invented synthetic scripts `h2-01` to `h2-22`, a second held-out set for run 6, written by an author session in an empty folder outside this repository that saw only `SPEC.md` (the behaviour brief and one format example, kept here) — never the phrase lists, the other scripts, `heldout/`, the findings register or the plan. `author-prompt.txt` and `author-session.jsonl` (the session's own log, the user name redacted) are the isolation record; `AUTHOR-NOTES.md` is the author's own note of each script's intent, read only from Task 0.12. Its expected transcript-level outcomes are written in Task 0.12. A held-out check like `heldout/`: never tuned to, never edited to make a run pass; same voices and builder (slot 0 the clinician, slot 2 the patient, slot 1 a third role).
- `heldout-3/` — (2026-10-24, validation-run6 plan Task 0.17, D16) the BLIND set for run 6: invented synthetic scripts `h3-NN`, written by an author session in an empty folder outside this repository that saw only `SPEC.md` (heldout-2's brief with the plan's changes: every material fact on a non-clinician line is said with a cue phrase of a section open to that speaker, the next patient's role is `next_patient`, 3 to 6 facts a script). `author-prompt.txt` and `author-session.jsonl` (the user name redacted) are the isolation record; `AUTHOR-NOTES.md` is read only from the plan's Task P.4. Nobody read its scripts before run 6: until then the only readers were the lints, and the suite ran only through `scripts\lint-held-out-set.py validation\heldout-3` (C12) until its cases were written. Its reference tail starts were copied into `REFERENCE_TAIL_STARTS` by a script that prints ids and integers only; its expected outcomes were written after run 6 (Task P.4, 2026-10-25). Never tuned to, never edited to make a run pass; same voices and builder (slot 0 the clinician, slot 2 the patient, slot 1 a third role).
- `heldout-4/` — (2026-10-26, validation-run7 plan Task 0.8, D6) the BLIND set for run 7: 22 invented synthetic scripts `h4-01` to `h4-22`, written by an author session in an empty folder outside this repository that saw only `SPEC.md` (`heldout-3`'s brief with four lines changed: the set number, task, date and id prefix), leak-checked in Task 0.7 against every frozen phrase list — the widened closings and greetings, the correction markers and both hedge lists. `author-prompt.txt` and `author-session.jsonl` (the user name redacted) are the isolation record; `AUTHOR-NOTES.md` is read only from the plan's Task P.4. Since Task 0.5 the test fixtures name it — the set `heldout-4`, no expected outcomes (`cases_written=False`), its reference tails from the `next_patient` role and every material non-clinician fact routed, 20 to 25 scripts of 3 to 6 facts each, as `heldout-3` — and since Task 0.8 a temporary test checks its scripts are present (by file name only), removed at Task P.4. Nobody reads its scripts before run 7: the only readers are the lints and the script that copied its reference tail starts into `REFERENCE_TAIL_STARTS` (ids and integers only), and the suite runs only through `scripts\lint-held-out-set.py validation\heldout-4` (C12). Its expected outcomes are written after run 7 (Task P.4). Never tuned to, never edited to make a run pass; same voices and builder (slot 0 the clinician, slot 2 the patient, slot 1 a third role).
- `rules/` — pass-rule files. `option-a-proposed.json` is decision 3.5's option (a), ratified unchanged as rule v1 on 2026-10-07 (recorded in `docs/testing/validation-harness.md`). `rule-v2.json` (2026-10-24, validation-run6 plan Task 4.3; decision 0.7 with D8, D14, D15 and D17) is rule v2: schema 2, the same top-level thresholds plus one row per set (`scripts`, `heldout`, `heldout-2`, `heldout-3`) with literal ceilings for the residue classes R1 (recogniser), R2 (tone only) and R3 (unbroken next patient, counted per encounter), a gate flag (the 50 and `heldout-3` are the gate; `heldout` and `heldout-2` are reported) and `heldout-3`'s uncertainty reported, not gated (so its row has no R2 ceiling). A schema-2 file needs `--set <name>`; rule v1's verdict is printed beside v2's.

Invented content only: never a real patient, consultation or recording. How to run and what the numbers mean: `docs/testing/validation-harness.md`.
