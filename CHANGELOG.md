- Phase 3A hardening stage, steps H1–H2 (2026-08-18): the note checker's Check 2 no longer hard-blocks on several classes of consistent note. An error-grade `contradiction` blocks saving, copying and Complete, so each of these was a false block against the plan's stated no-false-positives property: a negation crossing a clause boundary negated the next clause's symptom ("No fever; pain persists"); a negated or interrogative clause still produced a positive laterality claim ("No pain in the left knee"); a sentence end hidden behind a closing quote was invisible to the parser; bare product-strength wording ("Paracetamol 500 mg") blocked against another strength because the exclusivity test proved only that no token disqualified the context, never that any administration or schedule token was present; and a medication in one sentence could bind a strength in the next or borrow an administration witness from an unrelated clause. The witness that upgrades a dose pair to blocking now joins the claim's confidence and coordinates, so a low-confidence witness demotes to an acknowledgeable review warning instead of an unclearable error. Clause containment is then STRUCTURAL rather than checked: tokens are parsed as one list per clause, so cross-clause leakage is unrepresentable — a named clause type that only the tokeniser mints, which the type checker refuses to accept a flat token list for — rather than tested for at nine call sites that three successive review rounds each found one of incomplete. Two facts stay deliberately whole-assertion and are pinned — a symptom is affirmed only when the assertion carries no negation anywhere, and an anchor carrying both values (a bilateral statement) is dropped rather than compared. After four further cross-family rounds each found another bilateral or correlative wording the clause split still made one-sided ("not only left but right knee pain"), laterality differences were RE-GRADED, practitioner-ratified, from the blocking `contradiction` to a new acknowledgeable `laterality_mismatch` review warning — the rounds 21–24 dose precedent: the parser cannot mechanically establish shared-anchor bilateral wording, so the signal stays and the block goes, and a wrong-side line is caught by the clinician's acknowledgement rather than an unclearable block. Negated-symptom and exclusive-dose differences still block. Also user-facing: the Note tab now carries a standing reminder that the app never ticks, writes or proposes Cliniko's Informed Consent attestation checkbox, naming the full attestation the clinician is about to make; the "unmapped section" warning no longer directs the clinician to a heading that does not exist; a failed recovery no longer promises the session remains recoverable, nor that nothing was deleted (a failed transcript rewrite can remove a stale note); and a config load failure now shows the file and field to repair instead of only an exception class, rendered as plain text. ### Security
- Closed a clinical-content-in-logs gap in the payload tripwire (found by cross-family peer review, 2026-08-04). The filter scanned only `record.getMessage()`, but handler filters run *before* the formatter appends exception and stack rendering — so a routine `logger.exception(...)` around note construction could persist note text to the plaintext rotating log, and the module docstring claimed protection it did not provide. The filter now scans every channel `logging.Formatter` emits: message, pre-cached `exc_text`, the exact `exc_info` tuple, `stack_info`, and the remaining interpolated format fields. Four consecutive review rounds were needed because each fix was narrower than the defect class, so the scanned field list is now **derived from `LOG_FORMAT`** rather than hand-maintained — adding a field to the format scans it automatically. The docstring now states the limit it cannot cover (bare clinical text carrying no registered signature; `log_event`'s whitelist remains the primary control)
