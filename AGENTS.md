# Project: Privacy-First Cliniko Clinical Scribe

## What This App Does
A single-practitioner clinical scribe for two Cliniko clinics: a thin Chrome extension embedded in the Cliniko workflow plus a secure Windows desktop companion that records consultations, runs local Whisper transcription and local `gpt-oss-20b` note generation, and creates draft treatment notes through Cliniko's official API. No cloud processing of audio or transcripts; the clinician reviews and finalises every note in Cliniko. See `PLAN.md` for the full product plan.

## Database Notes
No database server: every store is files under `%LOCALAPPDATA%\ClinikoScribe`, each DPAPI-keyed for this Windows login.
- `sessions\<id>\` — one live or recoverable recording (`key.dpapi`, `encounter.enc`, `audio.enc`, transcript, `note.enc`, `generated.enc`, `saved-provenance.enc`, `write.enc`); removed at Complete or Discard, swept after 24 h.
- `audit\YYYY-MM\<id>.enc` — one content-free row per session under one store key, kept 7 years, exportable as CSV (`audit.py`).
- `past_sessions\<id>\` — the kept transcript, saved and generated notes and the name label under a per-entry key, written and verified before the session key goes (`past_sessions.py`); settings in `config\past_sessions.json` ("Until I delete them" or "7 years").
- The practitioner profile, style store and clinician config files — see the threat model and `docs/security/retention-schedule.md` (the authoritative list of what is kept and for how long).

## Local Run Steps
**Prerequisites:** Python 3.12+ (dev machine runs 3.14), Node 24 LTS, 24.15 or later (a 22.22.2+ release of the Node 22 line is also accepted by every extension tool — the `jsdom` test dependency narrowed it from 22.13+ on 2026-09-28; Node 23 and 25 are not), Google Chrome.

1. Clone the repo
2. `python -m venv .venv` then `.venv\Scripts\python.exe -m pip install -e ".\desktop[dev,ml]"` and `.venv\Scripts\python.exe -m pip install sounddevice` (the `[ml]` extra = faster-whisper/onnxruntime/huggingface_hub; `sounddevice` is deliberately not in pyproject — the test suite is absent-safe without it, but recording needs it), then the prose runtime from its pinned hashed wheel (the second setup-time network step; NOT part of `[ml]` because PyPI only has an sdist and a plain `[ml]` install would build from source): `.venv\Scripts\python.exe -m pip install --require-hashes --no-deps -r desktop\requirements-ml-prose.txt` then `.venv\Scripts\python.exe -m pip install --only-binary=:all: "diskcache>=5.6.1" "jinja2>=2.11.3"` and `.venv\Scripts\python.exe -m pip check`
3. Download the local ML models (one-time; with step 2's wheel install, one of the two setup-time network steps — the app's own only network use is the read-only Cliniko API client, never at startup or idle): `.venv\Scripts\python.exe scripts\setup-models.py` — **run this YOURSELF from a normal terminal (PowerShell/cmd), never from an agent shell**: agent shells on this machine are MSIX-virtualized and their `%LOCALAPPDATA%` writes land in a package-private location invisible to user-launched apps (`docs/lessons.md`). ~5.3 GiB with all four benchmark candidates and the language model; silero + whisper `small` alone ≈ 470 MiB; the `language-model` entry (the prose styles, note-learning plan Task 4.1) is Qwen3-4B-Instruct-2507 Q4_K_M from `unsloth/Qwen3-4B-Instruct-2507-GGUF`, 2.33 GiB, pinned by size + SHA-256, streamed with resume — `--only language-model` fetches it alone; the `speaker-embedding` entry (voice enrolment, practitioner-profile plan) is PINNED since Task 0.5 (2026-09-15): the WeSpeaker VoxCeleb ResNet34-LM ONNX export, ~25 MiB, SHA-256-verified like silero — a `.onnx.candidate` left by the Task 0.4 fetch is verified against the pin and promoted to `<name>.onnx` on the next run (Task 0.6), otherwise it is downloaded and verified before it is written; a run without `--only` includes it
4. `cd extension && npm install && npm run build` (bundle lands in `extension/dist`)
5. Register the native host: `.venv\Scripts\python.exe scripts\register-native-host.py` (per Windows user; rerun after any venv move or reinstall — installs to `%LOCALAPPDATA%\ClinikoScribe`, which must stay space-free and `.exe`-based or Chrome silently reports "host not found"; since PLAN.md Phase 6 it also writes and reads back the per-user Windows Error Reporting exclusions for `pythonw.exe`, `scribe-app.exe` and `scribe-host.exe` (`wer :` line) — run it from a normal terminal, since a write or check from an agent shell proves nothing here (`docs/lessons.md`); `--unregister` removes them)
6. Load `extension/dist` as an unpacked extension in `chrome://extensions` (Developer mode), pin its icon
7. **Fully restart Chrome** — window-close is not a restart when background mode is on; verify no `chrome.exe` remains before relaunching
8. Verify: with `scribe-app` running, the pinned icon shows a green **OK** badge (since 2026-09-28 the badge reflects the APP: grey **OFF** while it is closed, **REC** / **PAUSED** for a live recording, **!** when the link drops under one); `.venv\Scripts\scribe-app.exe` self-test passes 2/2. Then add each clinic on the app's **Clinics** tab: a name, your contact email and the clinic's Cliniko API key (the key of your own login — any role, as long as it has exactly one active practitioner record), then **Validate** — the app talks to Cliniko only then and to check the treatment note a recording belongs to (when you open it in Chrome, or reopen a linked recording), never at startup or idle on its own; the key goes to Windows Credential Manager and is never shown again. If the tab asks for the clinic web address, copy `<clinic>.<shard>.cliniko.com` from the address bar and Validate again. Clear a pasted key from Windows clipboard history afterwards (Windows key + V). After a protocol or manifest change (protocol v2 since 2026-09-27; the side panel, the Cliniko page script and the `sidePanel` / `scripting` permissions since 2026-09-28), rebuild the extension, reload it in `chrome://extensions` and fully restart Chrome — an old build shows a red ERR badge; `register-native-host.py` needs re-running only when the host's entry point or manifest changes. Recording needs the Session tab's consent tick each time (never pre-ticked, cleared after every Start); a session started from the desktop is "Not linked to a Cliniko note" and cannot be written back
9. QA suites: `desktop:` `ruff check . && mypy && pytest` (in `desktop/`); `extension:` `npm run qa`
10. Speaker measurement (Task 2.3, practitioner-run from a normal terminal once labelled recordings exist): `.venv\Scripts\python.exe scripts\measure-speakers.py <recordings-dir>` — see `docs/testing/speaker-measurement.md`

**Cloud (web) sessions are DISABLED for this project — practitioner decision 2026-09-05.** All work runs on the Windows host: do not start `/execute-loop`, a build, or a review from a Claude Code web session, and do not create cloud environments for this repo. The notes that follow are retained for the record only, from the one cloud run (2026-09-04): `python3.12 -m venv .venv && .venv/bin/pip install -e "./desktop[dev]"`, then `apt-get install -y libegl1 libgl1 libopengl0 libxkbcommon0 libfontconfig1 libdbus-1-3 libglib2.0-0` (PySide6 needs the EGL runtime before `QtWidgets` imports), and run the suite from `desktop/` as `QT_QPA_PLATFORM=offscreen SCRIBE_SKIP_INTEGRATION=1 ../.venv/bin/python -m pytest -q`. Expected host-only results, held as SETS rather than driven to zero: 8 items in `test_secure_storage.py` (no keyring backend), 3 in `test_status_and_app.py` (DPAPI), the 6 `TestWindowedPipeline` cases in `test_transcription.py` (numpy absent without `[ml]`), and 5 mypy errors (numpy stubs, Windows-only ctypes attributes). The `claude` binary there authenticates by environment token, so `/execute-loop` runs with the subagent executor and no cross-family peer (see `docs/lessons.md`). If a new session offers a cloud environment, decline it and choose your own computer.

**Launching the desktop app:** double-click `.venv\Scripts\scribe-app.exe` in Explorer, or run it from a PERSISTENT terminal (`.venv\Scripts\python.exe -m scribe_desktop.app` keeps console output — but since PLAN.md Phase 6 (2026-10-01) an uncaught exception prints NO traceback or message there or anywhere: one `uncaught_exception error_code=<type name> detail_code=main|thread|unraisable` line on the console and in `%LOCALAPPDATA%\ClinikoScribe\logs\scribe-app.log` (`scribe-host.log` for the host) is all you get, so debug from the type name and a reproduction; this launch runs `python.exe`, which is not excluded from Windows Error Reporting, and the Status tab says so). NEVER launch it from an ephemeral terminal (e.g. a chat Run button) — the closing terminal kills the GUI child (`docs/lessons.md`). Only one instance runs per user: a second launch shows "already running" and exits (named-mutex guard).

No `.env` needed — the project has no environment variables (secrets live in Windows Credential Manager; the offline ML kill-switches are set by the app itself, which also REMOVES an inherited `SSLKEYLOGFILE` or `LLAMA_CPP_LIB_PATH` at startup; `assert_offline_env` refuses either by name).

Machine-specific run notes (local absolute paths, personal DB endpoints, machine-local ports) belong in a gitignored `AGENTS.local.md`, not here — and never put secrets in it.
