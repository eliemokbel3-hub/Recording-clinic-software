# Wake card detail, part 4 — sections 8 and 9: paths, coordinating with other runs
Previous: c03-dispositions-and-records.md. This is the last file of the wake card's detail. Moved word for word from the wake card STICKY.md; this file has no headings of its own.

Contents, in order: section 8, paths: Plan; Logs; Spawn wrapper; Peer launcher; Watcher script; Files of a run; Added phases; Full contracts; Closing a finished run. Then section 9, coordinating with other runs: the standing prompt, three paragraphs.

- Plan (single source of truth): the active plan in `.cursor/plans/` — under worktree isolation the WORKTREE plan copy is authoritative. Where the file is: not always at the journal's `plan=` path — a release stamp archives a Completed plan BEFORE the merge, with the run live until teardown; find it by `/close-run` Step 1's `--plan` resolution, the one resolver. The identity string every `away` verb and `attest-check` takes stays the journal's `plan=` value wherever the file is.
- Logs: `.cursor/loops/<iso-id>/` (isolated runs) or `.cursor/loops/` (flat) — `stage-<N>-<role>.log`, `<runkey>-probe.log`, prompt files. Role-log rotation: the wrapper rotates an EXISTING role log at spawn, BEFORE its retained open — when the file exceeds 50 MB, or at every spawn under `LOOP_ROLE_LOG_ROTATE=leg` — to `<stem>.leg-<YYYYMMDD-HHMMSS>[-n].log` (the timestamp BEFORE the `.log` extension so `/retro`'s role-log scan ingests every archive; no-clobber — `-2`/`-3` on a same-second collision, a refusal rather than an overwrite when no unique name exists), announced as `SPAWN_WARN check=role-log-rotated` on ITS stdout, never a probe-log line; the pump is untouched, so one long leg can still finish above the threshold (no leg STARTS on an oversized file). NEVER write `*-spawn-stdout.txt` copies of a tee'd role log — the tee's stdout IS your channel.
- Spawn wrapper (every `claude -p` spawn/respawn/resume): `bash scripts/loop-spawn-wrapper.sh` by its EXACT granted path — ALL parameters are `LOOP_*` ENVIRONMENT-only (the param-file transport is CLOSED: the wrapper reads no value from a file and refuses if `.cursor/loops/spawn-wrapper.env` names any `LOOP_*` key) — v33.0 optional keys (D3/D4/D8): `LOOP_EDIT_SURFACE` (the spawned role's edit-surface ROOT NAME — `worktree` for executor/architect/delegate under isolation, unset for peers; must name a `LOOP_ESCAPE_ROOTS` member), `LOOP_ALLOW_PATH` (`<root>:<repo-relative path>[;…]` — a peer's authoritative plan file + its findings sidecar, its only legal writes; quote the value in a shell — `;` is a command separator), `LOOP_ISO` (THIS run's iso-id) and `LOOP_LIVENESS` (`<min>|off` — the SAME resolved value you pass the composer-run peer twin) ride to BOTH escape-check twins as `--edit-surface`/`--allow-path`/`--iso`/`--liveness` (the helper owns the verdict — §4 step 7 reads it); `LOOP_PASS`/`LOOP_PEER_ROUND`/`LOOP_CAP` (ALL THREE or NONE — a partial set refuses pre-START) ride the wrapper's `ROLE: start role=peer` as `pass=`/`peer_round=`/`cap=`, sequenced by the helper against the ACTUAL probe log via `--read-log` (the start still lands once through the retained descriptor); `LOOP_ROLE_LOG_ROTATE=leg` forces per-leg role-log rotation (the Logs line above); v41.0 optional key `LOOP_ROUTE_BIN` (router mode — under `router=on` ONLY: the realpath of `claude-switch-route` resolved at preflight; the wrapper asks the router for the spawn's `CLAUDE_CONFIG_DIR` and the launcher — §4 step 8, the same variable — for the round's `CODEX_HOME`; the wrapper's six refusals, the topology rule, the answer rule, and the `SPAWN_ROUTE` / `SPAWN_WARN check=router` / `SPAWN_WARN check=route-skipped` stdout lines: SKILL → `## Backends`, the Spawn wrapper paragraph) ; v48.0 optional key `LOOP_SURVIVE` (`on` or `off`; unset is `on` where the host can fork, `off` is one process, any other value refuses pre-START — the wrapper's split and what `survive=` in `<leg>.live` says: SKILL → `## Backends`, Roles that outlive the composer); `LOOP_SEAT` is NEVER yours to set — it is a watcher takeover's seat nonce, and the wrapper and the launcher strip it from every role — only DR-1's ENUMERATED emission set reaches the probe log (the native `SPAWN_WRAPPER_START`/`EXIT:<code>` pair plus the helper-emitted `ROLE: start`, escape-check, and exit-census records and, from v48.0, the leg's own `ROLE: end` — §3's journal bullet), with python3 + a blob-clean `scripts/loop-journal.py` validated fail-closed on the spawn path (the `.sh` is a thin exec shim over `scripts/loop-spawn-wrapper.py`, the ONE implementation on every host — the grant shape and the whole contract unchanged, `python3` REQUIRED on PATH, no bound tool on the spawn path; on a Windows-native host spell every `LOOP_*` path `C:/…` and separate `LOOP_ADD_DIRS` with `;`). The wrapper grant is COMPOSER-ONLY (a spawned role never holds edit + the wrapper grant unless trusted-equivalent), and BEFORE relying on it YOU verify its bytes against its committed git blob from OUTSIDE the script — `git hash-object -- scripts/loop-spawn-wrapper.sh` equals `git rev-parse HEAD:scripts/loop-spawn-wrapper.sh`, and `git hash-object -- scripts/loop-spawn-wrapper.py` equals `git rev-parse HEAD:scripts/loop-spawn-wrapper.py` (BOTH files from v45.0 — the shim and the implementation it runs); untracked/dirty/mismatch on either ⇒ do NOT invoke (spawn composer-owned or MUST-PAUSE). A hash check inside the mutable script is worthless. Canonical: SKILL.md → `## Backends (capability-conditional)`, the Spawn wrapper paragraph.
- Peer launcher (every composer-seat codex peer round on a run with a run worktree): `python3 -I scripts/loop-peer-launcher.py` by that EXACT shape, from the BASE checkout — ALL parameters are `LOOP_*` ENVIRONMENT-only and it takes no argument (§4 step 8 — the recipe, the status lines, the exit codes). Where a host asks for a grant, the grant is that exact shape; it is COMPOSER-ONLY — never added to a spawned role's grant list. BEFORE relying on it YOU verify its bytes against its committed git blob, exactly as for the wrapper — `git hash-object -- scripts/loop-peer-launcher.py` equals `git rev-parse HEAD:scripts/loop-peer-launcher.py`; untracked/dirty/mismatch ⇒ do NOT invoke. The launcher checks the two tools it calls (`scripts/loop-journal.py`, `scripts/loop-history-check.py`) itself. Canonical: SKILL.md → `## Backends (capability-conditional)`, the Spawn wrapper paragraph.
- Watcher script (the composer's and the operator's tool; NEVER on a role's grant list, and every subcommand refuses under a role's environment): `python3 scripts/loop-watchdog.py identity | seat | stop | tick | watch`. YOURS: `identity --base "<abs base>" --iso <iso-id> [--nudge-tag <tag> --nudge-grant <n>] [--state-dir "<abs dir>"]` (`--state-dir` exactly when the operator started `watch` with one) at Preflight and at every Resume whose `seat` line does not read `mark=yes` (read `seat` FIRST at a Resume — §7: a standing mark is the operator's stop, and this write would lift it) — print its two lines, and read its exit code as SKILL → Preflight step 17 states it (exit 3 with no `identity:` line: nothing was written; exit 3 after `mark=clear-failed`: the record IS written and takeover stays off); `seat --base "<abs base>" --iso <iso-id> [--state-dir "<abs dir>"]` (read-only: who holds the seat, the mark, the `watcher:` line; `--state-dir` under the same rule); `tick --base "<abs base>"` with NO `--act` (read-only verdicts and the per-run `legs=` count); `stop --iso <iso-id> --base "<abs base>" [--takeover-only]` at the operator's word (§7). NEVER yours: `watch` and `tick --act` — the OPERATOR starts the watcher outside any agent session, and both refuse inside one. The permission line is `Bash(python3 scripts/loop-watchdog.py:*)` — Preflight step 17 owns its read and its one offer.
- Files of a run. Beside the journal, in `<base>/.cursor/loops/`: `<iso-id>-composer` (your identity record), `<iso-id>-seat` and `<iso-id>-seat.gate` (the seat), `<iso-id>-notakeover` (the operator's stop mark), `<iso-id>-takeovers` (the takeover ledger) — never edited, and never removed by hand while the run is live (the one exception is the mark, where `identity` itself says `mark=clear-failed`); `/close-run` retires all five at a verified close. Beside the probe log, per leg: `<leg>.live` → `<leg>.exit`, with `<leg>.out` and `<leg>.err` under the split (`<leg>.<n>.*` for a leg value used twice — go by the `leg=` line inside).
- Added phases (worktree mode): `phases=` spans the whole remaining plan (every release group; the `groups=` key beside it on a tagged plan), so BEFORE spawning any phase newly added to the plan, atomically update the isolation journal's `phases=` (and `groups=` when a group's last stage moved) — the journal is the SOLE phase authority; the `-active` marker carries no phase key. Full rule: SKILL.md → `## Run isolation (worktree-per-run)`.
- Full contracts: `.agents/skills/execute-loop/SKILL.md` — this card compresses, it never overrides.
- Closing a finished run: `/close-run [--iso <iso-id>] [--no-pr] [--group stage-<N>]` — an agent-invocable skill, run next by the operator, or by an agent acting on the operator's request, after the loop's `retained-green` close — or, under a bound away grant with `merge` in scope, by the composer itself, its pull-request path only, the grant standing in for its confirm table (SKILL → `## Away mode` → Release work): the records commit on the run branch → ONE pull request (or the `--no-pr` local ff-only close) → the helper's squash-verified `run-close --outcome merged --merge-commit <sha>` → teardown (`merged → cleaned`; worktree + branch gone; a still-live `-active` marker → `.complete-<ts>`, none when the loop's stop already dispositioned it). The run itself never pushes — `/close-run` is the ONE carve-out (SKILL → Run isolation). A non-final release group's close is the same skill with `--group stage-<N>`, run by the composer inside the run (SKILL → `## Termination` → Group end): the group's pull request → the helper's `run-close --outcome group-merged --merge-commit <sha>` (the group record, then the fast-forward of the base and the worktree to one sha; the journal stays `active`, nothing torn down) → the run's own tail and the next group. Canonical: `.agents/skills/close-run/SKILL.md`.


Before any merge or deploy (canonical: SKILL → `## Coordinating with other runs`):

Coordinate with other running agents. Before you merge or deploy, find out which other runs are live and whether their plans touch the same files, migrations or release lane. Where they overlap, talk to the other agent and agree who goes first. Never wait on another agent indefinitely: if you hear nothing, check the real state yourself (open PRs, running deploys) and proceed when it is clear. Write down what you agreed in the plan's handoff note, or in the run's log folder once the run has merged.

Live runs are read from the run records the way `/start-session` classifies them (the journal's state and the ownership marker), never guessed. Where the host has no way to message another session, skip the talking and check the real state.
